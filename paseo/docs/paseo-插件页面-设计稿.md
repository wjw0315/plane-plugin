## 0. 这份设计稿要解决什么

Paseo 侧的看板页现在是「能跑」的裸实现：横滚列 + 卡片，字段只有编号、标题、优先级、指派人，没有顶栏、没有双视图、没有 chip、没有空态与 toast 分层。用户要的是**先还原成设计稿的样子**，看过了再决定改什么——所以这份稿子只锁**外观与交互骨架**，不锁业务功能范围。

### 0.1 与参照实现的三个前提差异

| 差异 | OpenChamber 面板 | Paseo 插件页 | 处理方式 |
| --- | --- | --- | --- |
| 渲染 | DOM + CSS | react-native 原语（`View`/`Text`/`Pressable`/`ScrollView`/`PanResponder`） | 尺寸/圆角/间距/字号按稿取值，**不引入 CSS** |
| 颜色 | 写死深色 token（`--bg/#0d0f12` 等） | 宿主主题 `theme.colors` | 走**宿主主题**，保证明暗主题都不刺眼；chip 类小色块允许硬编码（与设计稿同色） |
| 配置 | 面板内配置覆盖层 + service `config.json` | Paseo 设置页（`plane-settings-page.tsx`） | 页面内**不再做配置表单**，只保留「设置」入口跳转宿主设置 |

## 1. 页面骨架

```text
┌──────────────────────────────────────────────────────────┐
│ ●  Plane 任务看板        [列|列表]  [项目▾] [↻] [⚙]     │  顶栏 header
├──────────────────────────────────────────────────────────┤
│                                                          │
│                  主体：列视图 / 列表视图                   │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ 已移到「进行中」                            [撤销]        │  底部 toast（仅操作后出现）
└──────────────────────────────────────────────────────────┘
```

- **没有 footer**：参照实现底部的「宿主 / service 状态 + 设置」条，在 Paseo 侧没有对应物；连接态并进顶栏状态点。
- 顶栏高度 40，左右内边距 12，底部分隔线 1px（`border`）。

### 1.1 顶栏元素

| 元素 | 位置 | 规格 | 行为 |
| --- | --- | --- | --- |
| 状态点 `●` | 最左 | 直径 6，圆点 | 绿（`statusSuccess`）= 已连上且已拉到项目；灰（`foregroundMuted`）= 未配置或加载中 |
| 标题 | 状态点右侧 | 12px / 600 / `foreground` | 固定文案「Plane 任务看板」 |
| 视图切换 `[列|列表]` | 标题右侧 | segmented，两段各 2px×7px 内边距，10.5px 字 | 切「列」走看板、切「列表」走分组列表；**切换不重新拉数据**；选择不持久化（本次不做） |
| 项目选择 `[项目▾]` | 右侧 | 胶囊按钮，最大宽 140，11px | 点击**循环切到下一个项目**（Paseo 侧无原生下拉，用循环切换 + 长列表弹层二选一） |
| 刷新 `↻` | 右侧 | 文字按钮 | 重新拉 states + work items |
| 设置 `⚙` | 最右 | 文字按钮 | 跳转宿主设置页（Paseo 插件 settings 贡献点已有的入口方式） |

> 项目切换：优先做成「点击弹出一列项目名的浮层」，浮层超过 8 项时滚动。循环切换只在项目 ≤3 时启用。

### 1.2 主体

两种视图共用同一份 `states` / `workItems` 数据，切换只换渲染分支。

**列视图（board）**

```text
┌─ 待办 (3) ─┐ ┌─ 进行中 (2) ─┐ ┌─ 完成 (5) ─┐
│ ┌────────┐ │ │ ┌────────┐   │ │ ┌────────┐ │
│ │ 标题    │ │ │ │ 标题   │   │ │ │ 标题   │ │
│ │ XLMSC-1 │ │ │ │ XLMSC-2│   │ │ │ …      │ │
│ │ [高] (吴)│ │ │ └────────┘   │ │ └────────┘ │
│ └────────┘ │ │                │ │            │
│  拖到这里   │ │                │ │            │
└────────────┘ └────────────────┘ └────────────┘
```

**列表视图（list）**

```text
▾ 待办 (3)
   ┌────────────────────────────────────────┐
   │ 标题                    [高] (吴)       │
   │ XLMSC-1                                  │
   └────────────────────────────────────────┘
   移动到 [进行中 ▾]
▾ 进行中 (2)
   …
```

## 3. 组件规格

### 3.1 卡片

```text
标题（13px，最多 2 行，超出省略）
[编号]  [优先级 chip]  [(头像)]        [会话 chip]
```

- 编号：`XLMSC-<identifier>`，等宽数字（`fontVariant: tabular-nums`），`foregroundMuted`。
- 优先级 chip：胶囊，描边+深底+彩字；无优先级时不显示。
- 头像：直径 16 圆，取指派人名**末两字**；无人时显示「未指派」文字（不显示空头像）。
- 标签 chip：`workItem.labels` 每个渲染一个中性 chip（描边 `border`，字 `foregroundMuted`），最多 2 个，超出显示 `+N`。
- 会话 chip：卡片关联到 Paseo 会话时显示 `⌘ 会话`，点击直接唤起会话（紫色系 `#a78bfa` / 底 `#1b1630`）。
  - 当前 `plane.list-work-items` 不返回会话 id；会话 chip 依赖 `plane.resolve-session` 逐条反查会放大 N 次 RPC。**本期做法**：卡片渲染时若 `labels` 含 `paseo-<agentId>` 形态的标签，则直接从标签取 agentId 渲染 chip，不额外发 RPC。

### 3.2 列

- 列头：状态色点（直径 6，用 `state.color`，缺省 `foregroundMuted`）+ 状态名（11px/600）+ 右侧数量（`foregroundMuted`）。
- 空列：虚线描边空盒，文案「拖到这里」（列表视图文案为「这个状态还没有工作项」）。
- 拖拽悬停：整列描边变蓝、底变深。

### 3.3 列表视图

- 每列一个可折叠分组（默认展开），组头 = 状态色点 + 状态名 + 数量。
- 组内每行 = 卡片（同 3.1，去掉会话 chip 的点击区）+ 下方一行「移动到 [状态下拉 ▾]」。
- 状态下拉是**横向一排 pill 按钮**（不是真下拉，RN 无原生 select），点一个即改状态；当前状态高亮。

### 3.4 toast

- 成功：`已移到「进行中」` + 右侧「撤销」按钮（5 秒内可撤销，回到原列）。
- 失败：红色底，显示服务端错误文案（如 `拖拽失败：401 Unauthorized`）。
- 同时只显示一条，新的覆盖旧的。

## 4. 交互清单（本期必须实现）

| 动作 | 列视图 | 列表视图 |
| --- | --- | --- |
| 改状态 | 拖卡片到目标列（乐观更新，失败回滚 + 失败 toast） | 点「移动到」后的状态 pill |
| 打开会话 | 点卡片（位移 <10px 视为点按） | 点「会话 chip」或「⌘ 会话」按钮 |
| 切项目 | 顶栏项目按钮 | 同 |
| 切视图 | 顶栏段控件 | 同 |
| 刷新 | 顶栏 ↻ | 同 |
| 撤销 | toast 上的「撤销」 | 同 |

**保留现有实现的三点**（不要在重写中丢掉）：
1. `PanResponder` 拖拽 + `measureInWindow` 命中列的逻辑（现有 `hitTestColumn` / `columnRects`）。
2. 乐观更新 + 失败回滚原列。
3. 点卡片 → `plane.resolve-session` → `navigation.openAgent` 唤起会话。

## 5. 四种页面态

| 态 | 表现 |
| --- | --- |
| 未配置 | 整页提示「请在设置中配置 Plane base URL、API Key 与 workspace」+ 「去设置」按钮 |
| 加载中 | 顶栏状态点变灰，主体显示「加载中…」（保留现有文字，不做骨架屏） |
| 空项目 | 虚线空盒：「这个项目还没有状态」+ 引导去 Plane 配状态 |
| 出错 | 红色文字（`statusDanger`）显示服务端错误；顶栏状态点不变色 |

## 6. 本期不做（留给用户看后再定）

- 新建工作项（`＋` 按钮）—— 服务端已有 `createWorkItem`，但要补 RPC 契约
