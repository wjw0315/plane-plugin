# 04 视图切换 A↔B：分组列表 + 记住选择

## Parent

[OpenChamber Plane 扩展 Spec](../spec.md)

## What to build

在面板头部加一个两段开关（列 / 列表），切换两种结构完全不同的看板：

- **列**：已存在的横向列看板。
- **列表**：单列纵向，按状态分组，每组可折叠并显示数量；每张卡下方给「移动到」下拉代替拖拽。

两种视图读同一份数据，切换不重新请求、不丢筛选；改状态的行为（乐观更新 + 撤销）保持一致。选过的视图写进宿主 storage，重开面板沿用。

## Acceptance criteria

- [ ] 头部出现两段开关，当前视图有选中态
- [ ] 切到列表：渲染纵向分组，每组有数量，卡片下能选「移动到」并成功改状态（同样有撤销）
- [ ] 切回列：卡片数量与归属和切换前一致，说明是同一份数据换渲染
- [ ] 切换不触发新的列表请求（可在日志或假 Plane 计数里看到）
- [ ] 关闭再打开面板，回到上次选的视图
- [ ] storage 不可用（抛错）时退化成默认「列」，面板照常可用

## Comments

- **2026-11-16 已实现**：`openchamber/`（提交 `f010017`，版本 0.4.0）。
  - 面板头部两段开关（列 / 列表）；选择写宿主 storage 的 `plane.view`，启动时读回，读不到退默认「列」。
  - 列表视图：纵向按状态分组（可折叠、带数量），每张卡下方「移动到」下拉；卡片不参与拖拽，改状态走下拉。
  - 两视图共用同一份内存数据与同一套改状态行为（乐观更新 + 5 秒撤销 + 失败回滚）。
  - 假宿主实测：切到列表后分组正确渲染；切换前后 `service-request` 计数 5 → 5（没重新拉）；下拉改状态发出 `POST /patch-state`；日志可见 `storage.set key=plane.view value="list"`；控制台 0 错误。
  - **未验收**：真机上「关掉面板再打开仍是上次的视图」（需要在真机装好后点一次）。
